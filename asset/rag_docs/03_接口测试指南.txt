# 接口测试指南

## 一、接口测试基础

接口测试是验证系统组件间数据交互的正确性。核心关注点包括：请求参数校验、响应状态码、响应数据结构、业务逻辑正确性、异常处理。

一个完整的接口测试用例应包含：接口地址、请求方法、请求头、请求参数、预期状态码、预期响应体。

## 二、状态码规范

200：请求成功，返回业务数据
400：请求参数错误，需检查参数格式和必填项
401：未授权，Token 缺失或失效
403：无权限，Token 有效但无访问权限
404：资源不存在
500：服务器内部错误，需查看服务端日志

## 三、常见测试场景

参数校验测试：必填参数缺失、参数类型错误、参数超长、参数含特殊字符。

边界值测试：数值参数取最小值、最大值、最小值减一、最大值加一。

业务逻辑测试：正常业务流、重复提交、并发请求、状态回滚。

异常测试：依赖服务不可用、超时、返回异常数据。

## 四、接口测试示例

接口：POST /api/login
请求体：
{
  "username": "test_user",
  "password": "123456"
}

正常场景：
请求参数正确，预期返回 200，响应体包含 token 字段。

异常场景1：
username 缺失，预期返回 400，响应体提示"用户名不能为空"。

异常场景2：
password 错误，预期返回 401，响应体提示"用户名或密码错误"。

异常场景3：
连续 5 次密码错误，预期返回 403，响应体提示"账号已锁定"。

## 五、接口自动化测试建议

优先覆盖核心业务接口，再逐步扩展到边缘接口。

测试数据与测试代码分离，便于维护和复用。

使用断言库校验响应，包括状态码、字段类型、字段值、响应时间。

每次接口变更后，必须回归相关用例。
