# 历史 Bug 记录

## BUG-001 登录后跳转错误

模块：登录
等级：严重
优先级：P1
发现版本：v1.2.0
复现概率：必现
环境：Chrome 120 / Windows 11

复现步骤：
1. 打开登录页
2. 输入正确的用户名和密码
3. 点击登录按钮
4. 观察跳转目标

预期结果：跳转到首页，页面显示用户昵称和头像。
实际结果：跳转到订单列表页，页面能正常加载，但用户期望看到首页内容。

原因分析：登录成功后的跳转路由配置错误，代码中写的是 /orders 而非 /home。

修复方案：修改路由配置，跳转目标改为 /home。同时补充单元测试，防止后续再改错。

回归用例：login_password_correct、login_redirect_home。

## BUG-002 支付成功后订单状态未更新

模块：订单支付
等级：致命
优先级：P0
发现版本：v1.3.0
复现概率：必现（支付金额大于 0 时）
环境：Chrome 120 / Windows 11

复现步骤：
1. 选择商品下单，订单金额 99 元
2. 进入支付页，完成支付
3. 返回订单列表查看状态
4. 刷新页面后再次查看

预期结果：订单状态显示为「已支付」。
实际结果：订单状态仍显示为「待支付」，刷新后依然如此。

原因分析：支付回调接口未正确更新订单状态。具体原因是回调接口收到支付成功通知后，只更新了支付流水表，没有同步更新订单表的状态字段。

修复方案：修复回调接口的状态更新逻辑，增加订单表状态更新。同时增加补偿机制：每天凌晨对账，发现状态不一致的订单自动修正。

回归用例：order_pay_success、order_status_sync。

## BUG-003 密码错误超过 5 次未锁定账号

模块：登录
等级：严重
优先级：P1
发现版本：v1.2.5
复现概率：必现
环境：Chrome 120 / Windows 11

复现步骤：
1. 输入正确用户名，错误密码
2. 点击登录
3. 重复步骤 1-2 共 6 次
4. 第 6 次观察是否能继续尝试

预期结果：第 5 次失败后账号锁定 30 分钟，第 6 次尝试时返回 403，提示「账号已锁定」。
实际结果：第 6 次仍可继续尝试，未触发锁定。

原因分析：计数器逻辑错误。每次登录失败后，应把 Redis 中的失败计数加 1，但代码中写的是直接赋值，导致计数始终为 1，永远达不到 5 次的阈值。

修复方案：修复计数器逻辑，改为自增。同时增加锁定状态校验：每次登录前先检查账号是否被锁定，锁定则直接返回 403。

回归用例：login_password_wrong、login_password_locked。

## BUG-004 搜索框输入特殊字符导致页面报错

模块：商品搜索
等级：一般
优先级：P2
发现版本：v1.2.3
复现概率：必现
环境：Chrome 120 / Windows 11

复现步骤：
1. 在搜索框输入 <script>alert(1)</script>
2. 点击搜索

预期结果：搜索框过滤特殊字符，正常显示无结果。
实际结果：页面弹出 alert 弹窗，暴露 XSS 漏洞。

原因分析：前端未对输入做 XSS 过滤，直接把用户输入拼接到 HTML 中。

修复方案：前端增加输入过滤，转义 HTML 特殊字符。后端也增加校验，双重防护。同时对历史数据做一次 XSS 扫描。

回归用例：search_special_chars、search_xss_filter。

## BUG-005 订单金额显示精度错误

模块：订单详情
等级：一般
优先级：P2
发现版本：v1.2.1
复现概率：必现
环境：所有环境

复现步骤：
1. 下单金额为 19.99 元
2. 进入订单详情页查看金额

预期结果：显示 19.99 元。
实际结果：显示 19.989999 元。

原因分析：浮点数计算精度问题。金额在数据库中存储为 float，计算时产生精度丢失。

修复方案：金额统一用「分」为单位存储为整型，展示时除以 100 转换。同时对历史数据做迁移。

回归用例：order_amount_format、order_amount_calc。

## BUG-006 并发下单导致超卖

模块：商品下单
等级：致命
优先级：P0
发现版本：v1.3.1
复现概率：偶现（高并发时）
环境：生产环境

复现步骤：
1. 准备一件库存为 1 的商品
2. 用两个账号同时下单
3. 观察库存和订单

预期结果：只有一个订单成功，另一个提示「库存不足」。
实际结果：两个订单都成功，库存变成 -1。

原因分析：库存扣减未加锁。两个请求同时读到库存为 1，都判断可以下单，然后各自扣减，导致超卖。

修复方案：库存扣减改为数据库行锁或 Redis 分布式锁。同时增加库存流水记录，便于对账。

回归用例：order_stock_concurrent、order_stock_zero。

## BUG-007 用户头像上传后不显示

模块：个人中心
等级：一般
优先级：P2
发现版本：v1.2.4
复现概率：偶现（约 30%）
环境：Chrome 120 / Windows 11

复现步骤：
1. 进入个人中心
2. 上传头像图片（大小约 2MB）
3. 保存后刷新页面

预期结果：头像正常显示。
实际结果：头像显示为默认图，上传的图片未生效。

原因分析：图片上传接口偶发超时，前端未做重试，导致上传失败但用户无感知。

修复方案：上传接口增加重试机制，失败时提示用户重试。同时前端展示上传进度条。

回归用例：avatar_upload_success、avatar_upload_retry。
