# 产品需求文档（PRD）

本文档描述电商平台的核心功能需求，包含需求编号、描述、优先级、验收标准。

## 第一章 用户模块

### REQ-USER-001 用户注册

**需求描述**：用户可以通过手机号或邮箱注册账号。

**优先级**：P0

**验收标准**：
1. 手机号注册：输入手机号，获取验证码，验证通过后设置密码，注册成功。
2. 邮箱注册：输入邮箱，获取验证码，验证通过后设置密码，注册成功。
3. 手机号格式：11 位数字，以 1 开头。
4. 邮箱格式：符合 RFC 5322 标准。
5. 密码强度：8-20 位，必须包含大小写字母和数字。
6. 用户名唯一：同一手机号/邮箱只能注册一个账号。
7. 注册成功后自动登录，跳转首页。

**关联用例**：TC-USER-001 至 TC-USER-010

**关联 Bug**：BUG-012（手机号格式未校验）

### REQ-USER-002 用户登录

**需求描述**：用户可以通过用户名密码登录。

**优先级**：P0

**验收标准**：
1. 用户名不区分大小写。
2. 密码区分大小写。
3. 登录成功后返回 Token，有效期 2 小时。
4. 密码错误 5 次后锁定账号 30 分钟。
5. 账号锁定期间登录返回 403，提示「账号已锁定」。
6. 登录成功后跳转首页。
7. 支持记住登录状态 7 天。

**关联用例**：TC-USER-011 至 TC-USER-025

**关联 Bug**：BUG-001（跳转错误）、BUG-003（未锁定）、BUG-008（Token 未刷新）

### REQ-USER-003 密码找回

**需求描述**：用户可以通过手机号或邮箱找回密码。

**优先级**：P1

**验收标准**：
1. 输入注册手机号，获取验证码。
2. 验证码 5 分钟内有效。
3. 验证通过后设置新密码。
4. 新密码强度符合要求。
5. 找回成功后旧密码失效。

**关联用例**：TC-USER-026 至 TC-USER-035

**关联 Bug**：BUG-016（验证码未做时效校验）

### REQ-USER-004 修改密码

**需求描述**：登录用户可以修改密码。

**优先级**：P1

**验收标准**：
1. 需输入旧密码。
2. 新密码不能与旧密码相同。
3. 新密码强度符合要求。
4. 修改成功后旧密码立即失效。
5. 修改成功后需重新登录。

**关联用例**：TC-USER-036 至 TC-USER-045

**关联 Bug**：BUG-019（旧密码仍可登录）

### REQ-USER-005 绑定手机号

**需求描述**：用户可以绑定手机号。

**优先级**：P1

**验收标准**：
1. 输入手机号，获取验证码。
2. 验证码 5 分钟内有效。
3. 手机号不能被其他账号绑定。
4. 绑定成功后可用于登录和找回密码。

**关联用例**：TC-USER-046 至 TC-USER-055

**关联 Bug**：BUG-016（验证码未做时效校验）

### REQ-USER-006 用户注销

**需求描述**：用户可以注销账号。

**优先级**：P2

**验收标准**：
1. 注销前需二次确认。
2. 注销后账号无法登录。
3. 注销后数据保留 30 天，期间可恢复。
4. 30 天后数据彻底删除。

**关联用例**：TC-USER-056 至 TC-USER-060

**关联 Bug**：BUG-021（数据未清理）

## 第二章 商品模块

### REQ-PRODUCT-001 商品列表

**需求描述**：展示商品列表，支持分页和筛选。

**优先级**：P0

**验收标准**：
1. 默认每页 20 条。
2. 支持按分类筛选。
3. 支持按销量、价格排序。
4. 分页参数：page 从 1 开始，size 最大 100。
5. 深度分页（第 1000 页）响应时间 < 1 秒。

**关联用例**：TC-PRODUCT-001 至 TC-PRODUCT-015

**关联 Bug**：BUG-009（分页重复）、BUG-025（深度分页慢）

### REQ-PRODUCT-002 商品详情

**需求描述**：展示商品详情。

**优先级**：P0

**验收标准**：
1. 展示商品名称、价格、库存、描述、图片。
2. 商品不存在时返回 404。
3. 商品下架时展示「已下架」。
4. 缓存 5 分钟，修改后主动清除缓存。

**关联用例**：TC-PRODUCT-016 至 TC-PRODUCT-025

**关联 Bug**：BUG-024（缓存不一致）

### REQ-PRODUCT-003 商品搜索

**需求描述**：支持关键词搜索商品。

**优先级**：P0

**验收标准**：
1. 关键词支持模糊匹配。
2. 搜索内容做敏感词过滤。
3. 搜索内容做 XSS 过滤。
4. 搜索结果按相关度排序。
5. 无结果时展示「暂无相关商品」。

**关联用例**：TC-PRODUCT-026 至 TC-PRODUCT-035

**关联 Bug**：BUG-004（XSS）、BUG-014（排序错乱）、BUG-028（敏感词未过滤）

## 第三章 订单模块

**需求描述**：用户可以选择商品创建订单。

**优先级**：P0

**验收标准**：
1. 订单包含商品列表、收货地址、金额。
2. 库存不足时不能下单。
3. 地址不存在时不能下单。
4. 订单金额正确计算（含优惠券）。
5. 创建成功后返回订单 ID。
6. 同一请求 ID 只创建一次订单（幂等）。

**关联用例**：TC-ORDER-001 至 TC-ORDER-020

**关联 Bug**：BUG-006（并发超卖）

3. 支付成功后订单状态变为「已支付」。
4. 支付成功后库存扣减。
5. 重复支付返回 409。
6. 支付超时（30 分钟）订单自动取消。

**关联用例**：TC-ORDER-021 至 TC-ORDER-040

**关联 Bug**：BUG-002（状态未更新）

### REQ-ORDER-003 订单取消

**关联用例**：TC-ORDER-041 至 TC-ORDER-050

## 第十二章 全局需求

### REQ-GLOBAL-001 接口规范

**需求描述**：所有接口遵循统一规范。

**优先级**：P0

**验收标准**：
1. 返回结构统一：code、message、data。
2. code=0 表示成功。
3. 状态码符合 REST 规范。
4. 时间格式统一 ISO 8601。

**关联用例**：TC-GLOBAL-001 至 TC-GLOBAL-010

**关联 Bug**：BUG-033（时间格式不统一）

### REQ-GLOBAL-002 日志规范

**需求描述**：所有接口记录日志。

**优先级**：P1

**验收标准**：
1. 记录请求 ID、用户 ID、接口路径。
2. 记录请求参数、响应状态、耗时。
3. 敏感字段不记录。
4. 日志保留 30 天。

**关联用例**：TC-GLOBAL-011 至 TC-GLOBAL-020

### REQ-GLOBAL-003 监控告警

**需求描述**：关键指标需监控告警。

**优先级**：P1

**验收标准**：
1. 监控 QPS、响应时间、错误率。
2. 错误率 > 1% 告警。
3. P99 > 1 秒告警。
4. 告警渠道：邮件、短信、钉钉。

**关联用例**：TC-GLOBAL-021 至 TC-GLOBAL-030

### REQ-GLOBAL-004 限流

**需求描述**：接口需限流。

**优先级**：P1

**验收标准**：
1. 单 IP 每秒最多 100 次。
2. 单用户每秒最多 10 次。
3. 超限返回 429。
4. 响应头含 Retry-After。

**关联用例**：TC-GLOBAL-031 至 TC-GLOBAL-040

**关联 Bug**：BUG-026（短信未限流）

### REQ-GLOBAL-005 熔断降级

**需求描述**：依赖服务异常时熔断降级。

**优先级**：P1

**验收标准**：
1. 依赖服务连续失败触发熔断。
2. 熔断后快速失败。
3. 降级返回兜底数据。
4. 依赖恢复后自动恢复。

**关联用例**：TC-GLOBAL-041 至 TC-GLOBAL-050

## 附录

### A. 需求优先级定义

- P0：核心功能，必须有
- P1：重要功能，应该有
- P2：一般功能，可以有
- P3：边缘功能，可选

### B. 需求状态

- 草稿：需求编写中
- 评审中：需求评审
- 已确认：评审通过，待开发
- 开发中：开发进行中
- 已上线：功能已上线
- 已废弃：需求取消

### C. 需求变更流程

1. 提出变更申请
2. 评估影响范围
3. 评审变更
4. 更新需求文档
5. 通知相关方
